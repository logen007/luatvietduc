# UX review — 2026-11-05

Source review of public navigation, library/contact, customer chat and the staff
inbox, plus the knowledge/connections/backup panels. This is not a complete visual
audit or accessibility certification. The admin remains Vietnamese; public copy
uses VI/DE. Existing legal content, access rules and provider settings stay intact.

## This release: both sides of the chat

- Public menu/footer say “Trò chuyện” / “Chat”, matching the AI-first entry point.
- Failed chat initialization gives history an error/retry instead of endless loading.
- An acknowledged staff claim shows a loading state until the authorized content
  arrives; it no longer offers a second claim while the conversation is already human.
- Reply/note switches and snippets are disabled during upload or when reply access
  is unavailable. The compose placeholder reflects loading, closed and retry states.
- Staff keyboard submission respects text composition; touch controls have44px
  targets and visible keyboard focus. Mobile history/search inputs use16px to avoid
  automatic text-field zoom. The customer composer has a visible group focus ring.

## Follow-up groups implemented

1. `backup/useBackups.ts` owns session-scoped status, latest reads and a synchronous
   mutation gate. Loading, errors and empty history are distinct. An accepted job
   remains accepted if the next read fails; actions stay disabled until status is
   known again. Recovery identities stay in memory and clear on submission/session
   loss. Existing server job uniqueness and isolated restore checks remain intact.
2. `chat/drafts.ts` keeps up to 50 independent drafts in workspace memory. Switching
   conversations restores text and file references; acknowledged sends remove only
   that conversation's draft. Explicit account/Google navigation saves the active
   draft in tab-local storage for at most 15 minutes. Restoration is one-time and
   requires the requested conversation in the current server-owned list, with the
   same user or a guest conversation linked by the existing OAuth ownership flow.
   File URLs are rebuilt locally; no transcript, credential or recovery key is saved.
   Other drafts remain memory-only; this is not durable multi-device draft storage.
3. German keyword/category searches with no published results show an empty state
   and a return-to-library action without fabricating German legal content.

Connection forms now use the same session revision boundary and synchronous action
gate. Losing owner access unmounts unsaved credential fields, and delayed old replies
cannot update the next identity's form. Explicit session invalidation clears stored
staff drafts and account handoffs. Transcript403/404 clears customer private content
as well as staff content; transient read failures keep retryable work intact.

Regression additions use synthetic principals and local intercepted endpoints in
the existing CI: independent drafts, handoff expiry/ownership/URL rebuilding, actual
account navigation, owner role loss, backup duplicate clicks and write/read separation,
and an empty German search. No live provider, production database or customer chat
is a test target. This pass uses source review and CI; it is not a fresh visual audit
of every screen or a full security certification.

Do not fold those independent groups into a small requested correction. Keep changes
within the existing modules and release process; no new UI/test/release framework.
