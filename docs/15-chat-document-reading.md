# Customer image/PDF reading

Customer attachments stay private in the existing chat storage. Owner instruction on 2026-11-09 removes the confirmation dialog: sending supported images/PDFs automatically requests Gemini processing when AI is available. Files uploaded to storage but not sent in a chat message are not processed. Existing historical attachments are not processed retroactively merely because the application updates.

`gemini-documents-auto-v1` is recorded server-side as `documentProcessing` with provider, upload basis, timestamp and exact file IDs; this is an automatic processing record, not a claim of explicit consent. Previously recorded `gemini-documents-v1` remains readable for compatibility. The existing message transaction verifies file ownership, readiness, conversation, supported MIME and sizes, binds attachments, and creates the durable answer job. No schema change is required. Legacy consent metadata remains part of retry identity across account navigation; new uploads require no confirmation step. A new supported upload may restart an unassigned AI-only thread previously stopped by automatic file transfer, but never overrides an explicit human handoff, claim or staff response.

Limits: four JPG/PNG/WebP/PDF files, 10 MiB per file and 12 MiB total per bundle. Other files can still be sent to a specialist. The worker uses fixed private object coordinates, checks actual bytes and signatures, and sends bounded inline data to the configured Gemini model. It never publishes files or follows document URLs, links, QR codes or commands. Only customer context admitted by the existing per-turn protocol is supplied; internal notes are excluded. Document content is not embedded, indexed or turned into knowledge. Follow-up questions in the same conversation may use the latest server-marked attachment bundle. A later attachment message without a processing record cannot inherit permission for an earlier bundle.

AI is permitted to read, summarize and explain document language, with uncertainty about unreadable sections and references to file/page where available. Documents are customer evidence, not approved legal authority. A substantive legal conclusion or explicit request for a person can hand off. Missing pages, unreadable files, provider failures and bounded processing limits give a recoverable response and keep AI enabled. Human claim, a newer customer message, account ownership, provider/rule changes and runtime shutdown are checked through the existing generation/delivery boundary.

No live customer document or paid provider request was used in local verification. The existing isolated DB system suite exercises automatic processing/ownership, one durable job on retries, follow-ups, unavailable-AI specialist delivery, safe AI restart and explicit human-handoff preservation, unsupported input, provider truncation, missing storage records and a human claim during provider processing with mocked storage/Gemini. Unit checks cover limits, output validation and consent identity across login. Production model quality on actual scans remains dependent on image quality and the configured Gemini model.

Provider protocol reference: https://ai.google.dev/gemini-api/docs/document-processing

Owner retention policy (2026-11-09): adding an attachment no longer protects an otherwise disposable guest AI conversation. Its existing two-hour inactivity countdown remains visible. A forward migration gives recent attachment-only protected AI guests a fresh two-hour grace period; account history, pre-policy archives and explicit human handoffs stay protected. The expiry worker shares the guarded manual-deletion storage cleanup, skips unfinished uploads and active AI leases, respects backup locks, and retains SQL rows/object keys for retry if storage deletion fails. No production records are deleted by the migration itself. Rolling back application code is safe: the previous worker skips conversations with attachments.
