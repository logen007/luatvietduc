# Semantic knowledge pipeline

Specialists author title + body at `/admin/knowledge`; publication enqueues a durable PostgreSQL job in the same database transaction. No private message is an index source. Editing, unpublishing and deleting all enqueue cleanup. Worker reads only current eligible public sources, chunks with overlap and embeds with `gemini-embedding-001` (768 normalized dimensions). Fixed private Qdrant destination, pinned v1.20.0 image, on-disk cosine/HNSW vectors; payload contains IDs, revisions and scope only. Text/source truth stays in PostgreSQL.

Customer submissions include per-message `gemini-rag-v1` acknowledgment of the visible notice. Only these queries go to Gemini. Legacy clients retain the exact FAQ public-source-only path. Sensitive/personal case patterns hand off before external processing. One previous acknowledged user question may be included only when responding to the immediately preceding clarification. No full transcript, internal notes, identity or attachments go to the model.

Semantic retrieval selects up to three complete eligible articles from 32 vector candidates. The selector returns whole original paragraphs with source keys. Deterministic validation rejects invented text, partial paragraphs, unsupported keys, weak hits, excessive length and duplicate passages and omitted paragraphs explicitly marked as conditions/exceptions. The answer is extractive: it does not paraphrase or invent legal conclusions. Selection relevance/coverage still depends on the model and requires a real specialist-authored evaluation set before claims about semantic accuracy. Unsupported, ambiguous, quota-limited or interrupted requests enter the existing private staff queue. Citations and source revisions are rechecked under locks before sending. Human claim, newer question, publication withdrawal and provider/settings changes cancel stale work.

Index budget: 2,000 embedding calls/day, retries with backoff, 429 handling. Customer daily question budget uses existing admin setting; both embedding and selection sit inside one reserved question. This does not activate billing or guarantee the account has enough free quota. Successful chunk embeddings are checkpointed in PostgreSQL, so quota retries and vector rebuilds reuse completed work. Worker is serialized and bounded inside the existing app container; timer restarts on subsequent releases without manual VPS work. A new version is eligible only after the existing CI/backup/candidate/rollback checks.

## Installation and recovery

One-time reviewed helper installs only the separate private index service and app-scoped timer after verifying host headroom, exact source hashes and successful CI. Existing PostgreSQL, main compose, proxy and auto-release policies are unchanged. No host/public vector ports.

Database backup contains articles, index jobs, public chunk embeddings, chunk references and consent records. Qdrant is a **derived index**, not the source backup. After an actual database restore or vector-volume replacement, stop the indexing timer, enqueue every knowledge ID with an incremented generation/status pending, start the timer and wait for ready status before treating AI as ready. During rebuild, SQL generation/revision checks reject stale vectors and route questions to specialists. If the private collection is missing, the worker automatically requeues all articles and rebuilds it from cached public embeddings. Do not restore the live database merely to test this; use the existing isolated restore drill. Keep the previous application image for rollback; the additive schema can remain. Stop the knowledge timer and private index service when rolling back before this feature. Never delete volumes to roll back.
